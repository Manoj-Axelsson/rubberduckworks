
## The Pond Manager's Rule (#3)

### Leave the pond cleaner than you found it.


Software should be understandable before it is clever.

Documentation is part of the product.

Every commit should leave the codebase a little better than it found it.

Every file, folder, dependency, and document must justify its existence.

There are no loitering ducks in this pond.

Not because they are unwelcome, but because every duck has a purpose.

The Pond Manager's responsibility is simple:

to keep the water clear, remove what no longer creates value, and to ensure that every newcomer can find their way without unnecessary noise.

- If a file teaches, documents, enables, or creates value, it belongs.

- If it merely drifts, it is politely waddled away.

- There are no loitering ducks in this pond.

1. Every duck contributes.
2. Every file has a purpose.
3. Every commit leaves the water a little clearer.


*If you found yourself smiling while reading this, you've already met the Pond Manager.*
